## 4. Severity-ranked findings

### P1 / HIGH — H0: current main CI is red because the real-hook first-push fixture cannot reach the behavior it claims to test

Affected:
- scripts/Test-AgentGuards.ps1
- scripts/assert-repo-identity.sh
- .githooks/pre-push
- .github/workflows/domain-tests.yml
- docs/IMPLEMENTATION_STATUS.md evidence claims for M8.7 guard closure

Observed:
- direct PowerShell and shell remote-advance checks allow a positively absent new branch;
- the real-hook fixture S11h fails;
- other hook negative scenarios can still appear to pass because any early identity rejection also produces a blocked push.

Root cause:
New-HookFixture stores a canonical GitHub origin but adds a Git url.*.insteadOf rewrite to a local file transport. The identity guard obtains origin through git remote get-url origin. Git expands insteadOf for that command, so the guard sees file://... rather than the canonical GitHub URL and rejects the fixture before the hook can exercise the absent-branch path.

A local Git semantic reproduction during this audit confirmed that remote get-url returns the rewritten file URL while git config --get remote.origin.url returns the raw canonical configured URL.

Impact:
- required CI is red;
- S11f/S11g/S11i are potentially weak as behavioral hook proofs because an early identity failure can satisfy a generic nonzero expectation;
- M8.7 documentation saying the hook scenario was closed is no longer sufficient current evidence.

Required remediation:
- fix the fixture/identity-test seam without weakening production identity enforcement;
- positively assert that the hook reaches the intended race-check branch for each scenario, not merely that exit code is nonzero;
- keep all fixture transport local and fail closed;
- rerun all PowerShell, shell, and real-hook scenarios in CI;
- update evidence docs only after 100% fresh pass.

Acceptance:
Test-AgentGuards passes every scenario on Linux CI and supported local shell environments, and each hook negative test distinguishes the intended rejection reason from identity-preflight rejection.

### P2 / MEDIUM — P1 platform risk: Android denial classification after process restart

Affected:

Assets/WalkGame/Platform/Android/CSharp/AndroidStepSensorProvider.cs

Disposition:
